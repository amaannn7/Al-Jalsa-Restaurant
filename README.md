# Al Jalsa Restaurant | مطعم الجلسة

Website for Al Jalsa Restaurant, Al Murabba, Riyadh: an animated bilingual (English / Arabic, RTL)
site with the full menu, a WhatsApp ordering cart, catering and meeting enquiries, and an admin
dashboard for the restaurant.

- **Public site:** `/en` and `/ar` (Home, Menu, Order Online, Catering, Book a Meeting, About, Contact)
- **Admin:** `/admin` (menu, prices, photos, categories, restaurant details, website text, catering
  packages, reviews, gallery, enquiries inbox, admin users)

## Stack

| Part | Choice |
|---|---|
| Framework | Next.js 16.4 (App Router, Cache Components), React 19.3, TypeScript |
| Styling | Tailwind CSS 4, custom design tokens in `src/app/globals.css` |
| Design | Clean modern restaurant layout: dark rounded photo cards for heroes, white cards on linen, pill navigation. Newsreader + DM Sans (Noto Naskh Arabic + Readex Pro in Arabic) |
| Motion | Light CSS only: hero text rises on load, text fades in once, a few photo reveals and hover zooms (one shared IntersectionObserver), a reviews marquee. Motion for the cart, menus and dialogs. React `<ViewTransition>` for quick page fades. No scroll-jacking or smooth-scroll library. |
| Photos | Representative Unsplash stock photos at original resolution (under-4K originals upscaled with [Upscayl](https://github.com/upscayl/upscayl)), 3840px WebP through `next/image`; credits in `docs/photo-credits.md` |
| Data | PostgreSQL via Prisma 7 (`@prisma/adapter-pg`) |
| Auth | Email + password (bcrypt), signed httpOnly session cookie (jose), roles Owner / Editor |
| Images | Vercel Blob for admin uploads (local `public/uploads` in development) |
| Ordering | WhatsApp click-to-chat (`wa.me`) with a generated message |

Everything runs on free tiers: Vercel Hobby, Neon Postgres (free), Vercel Blob (included in Hobby).

## Deploy on Vercel (free)

1. **Put the code on GitHub.** Create a private repository and push this folder to it.
2. **Import it in Vercel.** vercel.com → Add New → Project → choose the repository. The framework
   (Next.js) and build command (`npm run vercel-build`, from `vercel.json`) are detected automatically.
3. **Add a database.** In the project: Storage → Create → **Neon** (Postgres) → Free plan → connect it
   to the project. This adds `DATABASE_URL` and `DATABASE_URL_UNPOOLED` automatically.
4. **Add image storage.** Storage → Create → **Blob** → connect. This adds `BLOB_READ_WRITE_TOKEN`.
5. **Add environment variables** (Settings → Environment Variables):

   | Name | Value |
   |---|---|
   | `AUTH_SECRET` | a long random string, e.g. the output of `openssl rand -base64 48` |
   | `ADMIN_EMAIL` | the owner's email for the first admin account |
   | `ADMIN_PASSWORD` | a strong password (12+ characters, letters and a number) |
   | `NEXT_PUBLIC_SITE_URL` | your address, e.g. `https://aljalsa-restaurant.vercel.app` (later your own domain) |
   | `NEXT_PUBLIC_ALLOW_INDEXING` | `false` while testing; `true` when you go live (lets Google index the site) |

6. **Deploy** (Deployments → Redeploy). The build applies the database migrations and fills the empty
   database with the verified menu, website text and settings. It never overwrites changes made later
   in the admin.
7. Open `https://your-site/admin`, sign in with `ADMIN_EMAIL` / `ADMIN_PASSWORD`, then change the
   password under **Account**. You can remove `ADMIN_PASSWORD` from Vercel afterwards.

Without a database the site still deploys and shows the built-in menu; the admin shows
"Database not connected" until step 3 is done.

### Custom domain
Vercel → Settings → Domains → add the domain and follow the DNS instructions. Then set
`NEXT_PUBLIC_SITE_URL` to it and `NEXT_PUBLIC_ALLOW_INDEXING=true`, and redeploy.

## Run locally

Requirements: Node 20.9+ and PostgreSQL (or a free Neon database URL).

```bash
npm install
cp .env.example .env          # fill in DATABASE_URL, AUTH_SECRET, ADMIN_EMAIL, ADMIN_PASSWORD
npx prisma migrate deploy     # create tables
npm run db:seed               # fill menu, text, settings, first admin
npm run dev                   # http://localhost:3000
```

Useful scripts: `npm test` (unit tests), `npm run typecheck`, `npm run lint`, `npm run build`,
`npm run db:studio` (browse the database), `SEED_RESET_MENU=1 npm run db:seed` (replace the menu
with the original seed menu; use with care).

## How ordering works

1. Customers add dishes (size, quantity, special instructions) to the cart. The cart is kept in the
   browser and re-priced against the live menu on every visit.
2. On **Order Online** they enter name, phone, takeaway or delivery (and address).
3. **Send order on WhatsApp** opens WhatsApp with the full order addressed to the restaurant's
   WhatsApp number (Admin → Restaurant details). The order is only placed when the customer presses
   send; the site says so clearly. A copy appears in Admin → Enquiries.
4. When the delivery fee is not set, the message says "Delivery charge: to be confirmed by the
   restaurant" and no total is invented.

Catering, meeting and contact forms work the same way.

## Content rules

- Nothing is invented: prices, dishes, calories and descriptions come from the restaurant's printed menu.
  Missing values show "Price on request" or are hidden.
- Reviews are added only by the restaurant, word for word. With none added, the site links to Google.
- See `docs/01-research-and-plan.md` for sources and open questions, and
  `docs/03-launch-checklist.md` before going live.
